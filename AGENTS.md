# EdiAgil — Agente Instructions

## Architecture

React 19 SPA (Vite + TypeScript + Tailwind CSS 4) with offline-first Dexie (IndexedDB), Firebase Auth + Firestore for sync, Gemini AI via Cloud Function proxy, and Lemon Squeezy payments.

- **Entry**: `src/main.tsx` → `src/App.tsx` (tabs: modules/students/attendance/grades; also admin dashboard, landing)
- **Local DB**: `src/lib/db.ts` — tables: subjects, notes, students, evaluations, grades, attendance, calendarEvents, materials, subjectModules, extractedEvents, uploadedDocs
- **Firebase**: `src/lib/firebase.ts` reads config from `firebase-applet-config.json` (gitignored). Firestore collections mirror Dexie tables. Rules: `firestore.rules` (limit of 2 subjects/year for free, trial-expired = free, client cannot write trial fields or change plan).
- **AI**: `src/lib/geminiClient.ts` calls proxy; `src/lib/gemini.ts` re-exports it. **API Key NEVER in frontend** — only in Cloud Function secrets.
- **Payments**: Lemon Squeezy (NOT Stripe). Checkout/portal/webhook in `functions/index.js`.
- **Cloud Functions**: `functions/index.js` (Node 22, GCFv2): `geminiproxy`, `health`, `activateTrial`, `resolveTrialExpiry`, `redeemLicenseKey`, `createLemonSqueezyCheckout`, `lemonSqueezyWebhook`, `createCustomerPortal`, `setupLemonSqueezyProducts`, `adminListTeachers`, `adminGetTeacherData`, `adminGetTeacherSummary`, `adminSearchStudents`, `searchStudent`, `adminGetStudentBoletin`, `adminGenerateStudentInsights`, `adminGetInstitutionStats`, `adminGetInstitutionAlerts`, `adminGenerateInstitutionInsights`, `getInstitutionalMetrics`, `getStudentRiskReport`, `adminGetSchoolConfig`, `adminSaveSchoolConfig`, `adminSaveGradingWeight`, `adminSavePeriodos`, `adminSavePlanRules`. Pure logic modules: `functions/lib/institution-alerts.js`, `functions/lib/school-config.js`, `functions/lib/grading-weight.js`, `functions/lib/periodos-plan.js`, `functions/lib/student-search.js`, `functions/lib/risk-calculator.js` (tested in `scripts/test-alerts.mjs`, `scripts/test-school-config.mjs`, `scripts/test-grading-weight.mjs`, `scripts/test-periodos-plan.mjs`, `scripts/test-search-student.mjs`, `scripts/test-risk-calculator.mjs`).
- **Dashboard filters (turno + nivel educativo)**: los filtros combinados viven en el SIDEBAR del admin (sección desplegable "Filtros" → `src/components/SidebarFilters.tsx`, debajo de "Dashboard Administrativo") y comparten estado con todas las vistas del dashboard vía `src/contexts/AdminFiltersContext.tsx` (`useAdminFilters()`: `turno`, `nivelEducativo`, `clearFilters`; el provider envuelve `CuadernoApp`). El `FilterBar.tsx` central se eliminó (retirado del layout del dashboard, no la lógica). `src/lib/dashboardFilters.ts` sigue siendo la fuente única de verdad (`TURNOS`, `NIVELES`, `TURNO_LABEL`, `NIVEL_LABEL`). Admin functions that return dashboard data accept OPTIONAL `turno`/`nivelEducativo`, sanitized server-side with whitelists `PERIODOS_VALIDOS` (`matutino|vespertino|nocturno`) and `NIVELES_VALIDOS` (`inicial|primaria|secundaria|universidad`); empty/missing = no filter; filters are applied in memory over subjects by institution (never interpolated in queries). Field names: `subjects.periodo` (turno) and `subjects.nivelEducativo` (both editable by teachers in `SubjectModal.tsx`). Functions honoring filters: `adminListTeachers`, `adminGetTeacherData`, `adminGetTeacherSummary`, `adminSearchStudents`, `adminGetInstitutionStats`, `adminGetInstitutionAlerts`, `adminGenerateInstitutionInsights`. Views: `AdminStudents`, `AdminInstitutionStats`, `AdminAlerts` receive filter props from `AdminDashboard`; Excel export filename includes active filters as suffix. `AdminDashboard` lee los filtros del context (ya no tiene estado local de filtros) y su buscador de docentes está centrado (`mx-auto`) con la lupa alineada verticalmente al texto (`flex items-center`).

- **Grading weight global (Módulo 4 del plan admin)**: `institutions/{id}.gradingWeight` stores how the institution computes final grades — `{ mode: 'tradicional' | 'competencias' | 'personalizada', weights?: { teoria, practica, apreciativa }, customWeights?: Record<string, number>, applyTo: 'global' | 'override', updatedAt }`. Client cannot write `institutions/*`; only `adminSaveGradingWeight` (admin) writes it, validating mode/applyTo whitelists, 0-100 ranges, sum = 100 (tolerance 0.01), and 2-12 categories for `personalizada`. Read is exposed as `adminGetSchoolConfig.gradingWeight` (via `gradingWeightOut`); missing/corrupt field falls back to default tradicional 30/60/10 + applyTo 'global' (backward compatible). Types: `src/types/firestore.ts` + `src/lib/adminApi.ts` (`DEFAULT_GRADING_WEIGHT`). UI lives as the "Ponderación" step of `AdminOnboarding.tsx` (mode cards, sliders, sum indicator, global/override selector); save calls `adminSaveSchoolConfig` + `adminSaveGradingWeight` in parallel and blocks save if percentages don't sum 100. Pure logic in `functions/lib/grading-weight.js` (errors as `GRADING_*` codes, translated in `functions/index.js`). This module ONLY adds the config layer — it does NOT change grade calculation; a future consumer of the calculation will read `gradingWeight` from `institutions/{id}` (or via `adminGetSchoolConfig`). `'competencias'` reinterprets the system's existing evaluation types (teorica/practica/apreciativa) as Saber/Hacer/Ser (no new evaluation types).

- Project: `ediagil-new-2026` (`.firebaserc` default)
- Hosting: serves `dist/`, SPA fallback to `index.html`, cache assets 1y
- Functions: Node 22, GCFv2, secrets: `GEMINI_API_KEY`, `LEMON_SQUEEZY_API_KEY`, `LEMON_SQUEEZY_WEBHOOK_SECRET`, `LEMON_SQUEEZY_SCHOOL_VARIANT_ID`
